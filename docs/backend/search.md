# Backend: search

Moved out of CLAUDE.md; read it before working in this area and keep it up to date.

- Search in one Conversation (#49, `SearchService`, `SearchController`): `GET /api/v1/conversations/{id}/messages/search?q=&before=` returns `{results, hasMore}`, newest first (`created_at` then `id`, both descending), `SearchService.PAGE_SIZE` (20) at a time; `before` is the `messageId` of the last result shown (the cursor is that Message's `(created_at, id)`; anything that is not a Message of that Conversation is a 400). Each result is `{messageId, conversationId, seq, senderId, createdAt, snippet}` (`SearchResult`); open it with the history's `aroundSeq`. **Matching** is PostgreSQL full-text search (migration `V16`): the text search configuration `message_search` is `simple` (no stemming, no stop words, so every language is treated alike) with the `unaccent` dictionary in front (the extension is created by the migration; it is trusted, so a database owner can create it), so case and accents are ignored ('cafe' finds 'Café', 'strasse' finds 'Straße', Greek tonos too); `message.search_vector` is a stored generated `tsvector` of `body` with a GIN index, so an edit replaces the searchable text, a deletion (null body) leaves nothing, and a caption is searchable because it is the body. Text without spaces (Chinese, Japanese) is one word to the parser, so it is found only from its start. `SearchQuery.parse` (lib) splits the typed text: everything goes to `websearch_to_tsquery` (quotes for a phrase, `-word` to exclude, `or`; it accepts anything, so no query can cause an error) except the last word while it is being typed, which becomes a prefix `'word':*` for `to_tsquery`, built only from letters, digits and combining marks so nothing typed can escape its quotes; a negated last word, one inside an open quote, or any query using `or` (the prefix is joined with "and", which would turn 'lunch or din' into both) stays with the rest. Earlier words must match whole ('meet moved' does not find 'meeting moved'). Both statements build the query with the SQL function `message_search_query(words, prefix)` (V16), which never hands `to_tsquery` an empty text (it would log a NOTICE). Only Messages with text are searched, and a query that only excludes (`-cafe`, whose `querytree` is `T`) finds nothing rather than everything else. **Exclusions** are in the query (`MessageRepository.searchConversation`): deleted for everyone, hidden by the caller (`message_hidden`), at or before the caller's join point; the membership check comes first, so a non-participant, an unknown Conversation and someone who left or was removed all get the uniform 404. **Snippet**: `ts_headline` with the same query (`MessageRepository.snippets`, one query per page), in its default mode: up to 24 words from about the first match (a short text comes back whole, line breaks kept; the fragment mode was dropped because it cut a number at the very end of the text, 'note 12' became 'note'), each matched word between `SearchResult.MATCH_START` (U+E000) and `MATCH_END` (U+E001); those two characters are removed from the text first, so typing them cannot fake a mark; the client must render the snippet as text, never HTML. A Message deleted between the search and the snippet query is dropped from the page (it is no longer a result). **Limits**: `q` is `@ValidSearchQuery` (the `TextRules`: not blank, at most 100 code points, no NUL; and at least 2 code points once stripped), all a 400 under `errors.q`; `app.search.max-per-minute` (30) per User through `RateLimiter`, counted for every accepted call before anything else, including the membership check (found or not, any Conversation; a query refused by validation never reaches the count), 429 with `Retry-After`. The migration rewrites `message` and builds the index without `CONCURRENTLY` (fine at this size). Known limits: a snippet does not say whether text was cut at either end; a `before` cursor is accepted for any Message of the Conversation (also one the caller hid or that predates them: it only sets a position); a page can be one short when a result was deleted between the two queries; a single very long word (no spaces) comes back in full; `created_at` comes from each instance's clock, so instances should run time sync for the order to match the Sequence. Tests: `MessageSearchTests`.
- Search across all Conversations (#52, `SearchService.searchAll`): `GET /api/v1/messages/search?q=&before=` has the same rules, limits and shape as the search in one Conversation, and every result carries its `conversationId`. `MessageRepository.searchAll` joins the caller's **current** `participant` rows, so a Conversation they left or were removed from (the row is deleted) is not searched, someone added back finds only what was said after they rejoined, and each Conversation keeps its own join point; deleted, hidden, text-less and exclusion-only queries are handled exactly as in one Conversation (same `message_search_query`, same snippets). `before` is only a position (the Message's `(created_at, id)`): any Message is accepted (an unknown id is a 400), results still come only from the caller's own Conversations, so leaving or being removed from the Conversation of the last result shown does not stop the paging. Both searches share the one `rl:search:` allowance of 30 a minute. Tests: `AllConversationsSearchTests` (also an edit found by its new text only, across Conversations); `MessageSearchTests.aNumberAtTheEndOfTheTextStaysInTheSnippet` guards the headline mode.
