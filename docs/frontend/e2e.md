# Frontend: Playwright e2e suite (not run by agents)

- Playwright's `webServer` starts the backend (`./mvnw spring-boot:run` in `backend/`, which brings up the compose stack incl. Mailpit) and the frontend as a **production build on its own port, 3002** (`bun run build && next start -p 3002`, built into `.next-e2e` through `NEXT_DIST_DIR`, fresh every run, never reusing a server that is already there), so the suite neither depends on nor disturbs the development server on 3001 that you may be starting and stopping; the backend is given `APP_CORS_ALLOWED_ORIGINS` for that origin (`FRONTEND_URL` in `e2e/playwright-urls.ts`). `E2E_DEV=1` serves `next dev -p 3002` instead for quick iteration, at the price of cold-compile slowness and flakes. Every test runs in four projects: `desktop-light`, `desktop-dark`, `phone-light`, `phone-dark` (the app follows the system colour scheme by default, which each project sets; `openSession()` contexts inherit it), so the whole suite takes about ten minutes and tests that look at the project name use `startsWith("desktop")` / `startsWith("phone")`. It **refuses to adopt a running backend** (it would spend that backend's real throttle allowance and leave test data in it): stop your backend before `bun run e2e`, or set `E2E_REUSE_SERVERS=1` if you started it yourself with the raised limits below. It raises the backend's per-IP, lookup, group and Message-send throttles through `APP_OTP_MAX_SENDS_PER_IP_PER_HOUR`, `APP_LOOKUP_*`, `APP_GROUPS_*` and `APP_MESSAGES_*` environment variables (the per-email code limit stays at 5 an hour because a test exercises it, so use a fresh email per test); if you start the backend yourself, pass the same ones or a long suite will meet 429s. Test data is never cleaned up; every test uses unique emails. `e2e/support` has the `openSession()` fixture (a page in a fresh browser context, for tests with several people) and `createVerifiedAccount()` (signs up and verifies through the backend, reading the code from Mailpit's REST API at `localhost:8025`) and `signIn()`.
